# Текст для анкеты

Этот файл нужен как черновик для анкеты перед распределением на стажировку.

Ссылка на портфолио: <https://github.com/JohnGreen1981/ai-automation-portfolio>

## Короткое описание

Я занимаюсь prompt engineering и AI-автоматизациями. Я не позиционирую себя как ручной разработчик, который пишет код с нуля: для реализации использую AI-coding assistants вроде Codex и Claude Code. Моя роль — поставить задачу, спроектировать workflow, собрать прототип, проверить результат и упаковать его в понятный сценарий для пользователя.

## Вариант на 2-3 предложения

Я начинающий AI automation / prompt engineering специалист. Умею собирать прикладные workflows с помощью AI-coding assistants: Telegram-боты, обработка аудио и текста через AI, интеграции с API, n8n-сценарии, базовый Docker/VPS-запуск и понятная документация. Продвинуто использую Claude Code и Codex: skills, MCP servers, hooks, проектные инструкции, межсессионную память и wiki по методу Карпатого. Работал с VS Code, имею базовые навыки PyCharm и Google Colab. Ищу стажировку, где смогу делать реальные автоматизации и быстро расти за счет практики.

## Вариант подробнее

Я заканчиваю обучение по prompt engineering и созданию автоматизаций. Мой главный интерес — превращать LLM из "чата" в рабочий инструмент: принять данные, обработать их, структурировать результат, показать пользователю понятный output и оставить возможность проверки.

Я честно разделяю свою роль и роль разработчика: я пока не пишу код с нуля самостоятельно. Вместо этого использую Codex, Claude Code и похожие инструменты как рабочую агентную среду: описываю задачу, декомпозирую логику, настраиваю проектные инструкции, skills, MCP servers и hooks, сохраняю межсессионный контекст, проверяю результат, тестирую пользовательские сценарии, нахожу ошибки и добиваюсь работающего прототипа.

В портфолио я хочу показать несколько практических проектов: Telegram-боты, speech-to-text сценарии, LLM-постобработку, domain-specific ассистентов и инструменты для проверки результатов. Для меня важно не только написать промпт, но и собрать весь путь пользователя: вход, обработка, ограничения, обработка ошибок, документация и запуск.

По курсу "Промт-Инжиниринг 2.0" у меня есть практическая база по продвинутому prompting, GPTs/Actions, OpenAI Playground, n8n, API/HTTP-интеграциям, Telegram/Gmail/Google Sheets-сценариям, основам работы с данными, Google Colab/Jupyter Notebook и базовым подходам LangChain: ReAct и Tool/Function Calling.

## Как говорить про код

Я не называю себя программистом в классическом смысле и не утверждаю, что пишу код с нуля без помощи. Я использую Codex / Claude Code как инструменты реализации и управления рабочим контекстом: ставлю задачу, описываю логику, настраиваю агентные инструкции, проверяю изменения, тестирую сценарии и добиваюсь работающего результата. Поэтому моя ценность сейчас — не в ручном написании кода, а в умении превращать идею в рабочий AI-assisted прототип.

## Что не стоит писать

- Не писать, что "я эксперт", если речь о стажировке.
- Не писать "я Python-разработчик" или "сам написал backend", если код создавался через Codex / Claude Code.
- Не обещать production-level DevOps, если в проекте только базовый Docker/VPS.
- Не выкладывать приватные данные, реальные токены, личные переписки, клиентские материалы.
- Не перегружать анкету списком технологий без объяснения, какие задачи они решали.
