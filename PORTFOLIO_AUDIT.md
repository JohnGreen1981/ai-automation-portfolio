# Portfolio Audit

Дата аудита: 2026-05-01.

Цель: понять, какие проекты можно показывать в портфолио, в каком формате и что нужно почистить перед GitHub.

## Главный вывод

Не публиковать текущие рабочие папки напрямую.

В большинстве проектов есть один или несколько рисков:

- реальные `.env`, ключи, service account JSON или локальные конфиги;
- личные Telegram ID, VPS-пути, домены, базы, истории и логи;
- отсутствие отдельного git-репозитория;
- служебные агентные файлы `.agents/`, `.claude/`, `.codex/`, `.cursor/`;
- `.venv`, `__pycache__`, локальные базы, PDF/исходники с возможными правами третьих лиц;
- README написан для себя, а не для внешнего проверяющего.

Правильная стратегия: сделать отдельные чистые portfolio-версии проектов или case studies, а не выкладывать рабочие директории.

## Позиционирование

Публичная рамка должна быть честной:

> Я не позиционирую себя как разработчик, который пишет код с нуля вручную. Я проектирую AI-workflow, формулирую требования, использую Codex / Claude Code как инструменты реализации, проверяю результат, тестирую сценарии и довожу прототип до понятного рабочего состояния.

В кейсах не писать "я написал backend" или "я разработал на Python" без уточнения AI-assisted роли. Лучше писать:

- спроектировал workflow;
- сформулировал требования и промпты;
- собрал AI-assisted прототип;
- проверил сценарии;
- довел до рабочего MVP;
- подготовил документацию и запуск.

## Security blockers

Перед любым GitHub-пушем:

- Не пушить рабочие папки целиком.
- Не пушить `.env`, `.env.*`, `.keys`, `keys.md`, service account JSON, локальные БД, историю запросов, логи.
- Заменить реальные Telegram ID, домены, VPS-пути и project refs на нейтральные примеры, если они не нужны для кейса.
- Проверить `git status --ignored` и `git ls-files` перед публикацией.
- Для файлов, где уже лежали реальные ключи, рассмотреть ротацию ключей до публикации.

Критичные локальные сигналы, найденные при аудите:

- `Учет доходов и расходов/.keys`
- `Учет доходов и расходов/skillful-radar-485213-u2-e807a67c3b7b.json`
- `Учитель сербского /.env`
- `Учитель сербского /.env.example`
- `Нутрициолог/keys.md`
- `Нутрициолог/nutri-bot/.env`
- `Секретарь собраний/.env`
- `Секретарь собраний/.env.vps`
- `Юрий/legal-verify/.env`

Значения секретов в портфолио не переносить и не цитировать.
