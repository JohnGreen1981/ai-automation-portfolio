# Чеклист перед публикацией на GitHub

## Содержание

- [ ] Выбраны 3-5 проектов для показа.
- [ ] Для каждого проекта написан короткий case study по шаблону.
- [ ] В README нет пустых `TODO`, кроме сознательно оставленных планов.
- [ ] Есть понятный первый экран: кто я, чем занимаюсь, что умею, какие кейсы смотреть.
- [ ] Есть ссылка на портфолио, которую можно вставить в анкету.
- [ ] Для каждого проекта создан отдельный clean repo или принято решение "case study only".
- [ ] Главный `Portfolio` ссылается на отдельные GitHub-репозитории, а не на рабочие исходные папки.

## Безопасность

- [ ] В репозиторий не попали `.env`, API-ключи, токены, базы с личными данными.
- [ ] Все скриншоты обезличены.
- [ ] В кейсах нет имен клиентов, если нет разрешения.
- [ ] В истории git нет секретов.
- [ ] `.gitignore` закрывает локальные файлы, кэши, окружения и приватные заметки.
- [ ] Исходные рабочие папки не публиковались напрямую.
- [ ] Clean repos имеют свежую git-историю без секретов из рабочих проектов.
- [ ] `AGENTS.md` / `CLAUDE.md` в clean repos есть и являются публичными sanitized-доками, а не копией внутренних рабочих инструкций.

## Качество GitHub-страницы

- [ ] README читается за 2-3 минуты.
- [ ] Кейсы названы человечески, а не только техническими именами папок.
- [ ] В каждом кейсе есть "задача -> решение -> стек -> результат -> что дальше".
- [ ] Не больше 5 главных кейсов, чтобы портфолио выглядело собранным.
- [ ] Есть отдельный файл с текстом для анкеты.
- [ ] Публичные README / AGENTS / CLAUDE / SECURITY / CLEANUP docs написаны на русском или есть осознанная английская версия.

## Проверка перед отправкой анкеты

- [ ] Открыть репозиторий в приватном окне браузера.
- [ ] Проверить, что ссылки работают.
- [ ] Проверить мобильный вид README.
- [ ] Отправить ссылку себе в Telegram и открыть как внешний человек.
- [ ] Убедиться, что первые 30 секунд просмотра дают нормальное впечатление.
