# Чеклист перед публикацией на GitHub

## Содержание

- [x] Выбраны 3-5 проектов для показа.
- [x] Для каждого проекта написан короткий case study по шаблону.
- [x] В README нет пустых черновых плейсхолдеров, кроме сознательно оставленных планов публикации.
- [x] Есть понятный первый экран: кто я, чем занимаюсь, что умею, какие кейсы смотреть.
- [x] Есть ссылка на портфолио, которую можно вставить в анкету.
- [x] Для каждого проекта создан отдельный clean repo или принято решение "case study only".
- [x] Главный `Portfolio` ссылается на отдельные GitHub-репозитории, а не на рабочие исходные папки.

## Безопасность

- [x] В репозиторий не попали `.env`, API-ключи, токены, базы с личными данными.
- [x] Все скриншоты обезличены.
- [x] В кейсах нет имен клиентов, если нет разрешения.
- [x] В истории git нет секретов.
- [x] `.gitignore` закрывает локальные файлы, кэши, окружения и приватные заметки.
- [x] Исходные рабочие папки не публиковались напрямую.
- [x] Clean repos имеют свежую git-историю без секретов из рабочих проектов.
- [x] `AGENTS.md` / `CLAUDE.md` в clean repos есть и являются публичными sanitized-доками, а не копией внутренних рабочих инструкций.

## Качество GitHub-страницы

- [x] README читается за 2-3 минуты.
- [x] Кейсы названы человечески, а не только техническими именами папок.
- [x] В каждом кейсе есть "задача -> решение -> стек -> результат -> что дальше".
- [x] Не больше 5 главных кейсов, чтобы портфолио выглядело собранным.
- [x] Есть отдельный файл с текстом для анкеты.
- [x] Публичные README / AGENTS / CLAUDE / SECURITY / CLEANUP docs написаны на русском или есть осознанная английская версия.

## Проверка перед отправкой анкеты

- [ ] Открыть репозиторий в приватном окне браузера.
- [ ] Проверить, что ссылки работают.
- [ ] Проверить мобильный вид README.
- [ ] Отправить ссылку себе в Telegram и открыть как внешний человек.
- [ ] Убедиться, что первые 30 секунд просмотра дают нормальное впечатление.
